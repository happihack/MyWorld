# MY WORLD IN A BOX

## Full Godot 4.7.2 Mobile Game Development Specification

You are an expert Godot 4.7.2 game developer, mobile game architect, simulation designer, UI/UX designer, gameplay programmer, systems designer, and technical lead.

Your task is to DESIGN AND BUILD a complete Android mobile game called:

# MY WORLD IN A BOX

Do not treat this as a small prototype.

Build it as the foundation of a long-running, highly replayable, deeply interactive mobile simulation game with an architecture capable of supporting a world that continuously grows, civilizations that evolve, persistent inhabitants with individual lives, emergent stories, environmental simulation, player interaction, discoveries, technological progression, historical memory, and eventually civilizations discovering that their world exists inside a box.

The game should be easy to understand within the first minute but capable of producing hundreds of hours of emergent gameplay.

Target:

* Godot 4.7.2
* Android first
* Touchscreen first
* Portrait and landscape support where practical
* Mobile hardware constraints must be respected
* GDScript unless there is a compelling technical reason to use another Godot-supported technology
* Offline-first
* Persistent save data
* No mandatory account
* No mandatory internet connection
* Architecture should allow future multiplayer/cloud features without requiring a rewrite

The game must be fun even when the player only spends 2–5 minutes with it, but should reward returning repeatedly throughout the day.

# 2. PRIMARY DESIGN PHILOSOPHY

The central design principle is:

> THE PLAYER DOES NOT CONTROL THE WORLD. THE PLAYER INTERACTS WITH THE WORLD.

If the player touches a person, that person should not simply receive a command.

Instead, the interaction should be interpreted according to:

* location
* personality
* current activity
* relationship with the player
* culture
* beliefs
* fear
* curiosity
* knowledge
* current needs
* nearby events
* memories
* previous player interactions

The same interaction should produce different results from different inhabitants.

Example:

Player taps a farmer.

Farmer might:

* look toward the touch
* become frightened
* investigate
* wave
* pray
* run
* report it to another person
* interpret it as weather
* believe it was a divine event

A scientist might react completely differently.

A child might be fascinated.

A religious leader might interpret it as a sign.

A skeptic might dismiss it.

This emergent interpretation system is one of the game's most important mechanics.

# 4. THE WORLD

The world is a persistent tile/grid-based environment.

Build the simulation so the world can become substantially larger over time.

Do NOT hard-code a tiny fixed map.

Use a scalable world architecture.

Recommended architecture:

* chunk-based world
* deterministic procedural generation where appropriate
* sparse storage for mostly empty regions
* active simulation zones
* sleeping/inactive simulation zones
* tile metadata
* entity registry
* persistent entity IDs
* world coordinates
* chunk coordinates
* saveable world state

Example:

WORLD
├── Chunk 0,0
├── Chunk 1,0
├── Chunk 0,1
├── Chunk -1,0
└── etc.

The player should initially see only a small section.

As the civilization expands, more world becomes relevant.

---

# 5. WORLD SIZE

Begin with a manageable world.

Example initial world:

64 x 64 tiles

But architect it to support:

128 x 128

256 x 256

512 x 512

and potentially larger through chunk streaming.

Do not load enormous worlds into memory unnecessarily.

Only actively simulate what needs to be simulated.

# 54. AI SIMULATION LEVELS

Use simulation tiers.

### Tier 0 — Dormant

Entity is far away and barely simulated.

### Tier 1 — Abstract

Entity participates in statistical simulation.

### Tier 2 — Regional

Entity has approximate behavior.

### Tier 3 — Active

Entity receives detailed behavior.

### Tier 4 — Player Focus

Selected person receives maximum detail.

This allows thousands of inhabitants without requiring thousands of fully active AI agents.

The game should generate consequences.
